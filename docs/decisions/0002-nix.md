# Nix for project reproducibilty

## Context and Problem Statement
Our implementation should be reproducible across research cites while being able to easily share/build.
The current standard is DeGAUSS which uses containers to easily transfer the same shell between cites. However,
implementations using Nominatim must link OSM/Tiger files and if using many packages for analysis should be 
optimally be bit-for-bit reproducible. Hashing the required files and dependencies for analysis should be sufficient.
There are situations where file-hash-pinning > version-pinning for reproducing the same analysis and avoiding supply-chain issues.


## Considered Options
* Git repository
* Nix Flakes
* Nix

## Decision Outcome
Using a combination of a Git Repo and "Nix Flakes" because it is easy enough to transfer a hashed file for confirmation or the repository with the 
flake.lock file to make sure dependencies are the same as well. Transferring the git repository with the flake and the hash for the resulting Nominatim database 
allows for different study cites to confidently rebuild the database.

### Consequences:

* Bad, Relies on converting nix flakes into docker/apptainer containers instead of written directly
    * May lead to headaches downstream: 
    * potential for users unfamiliar with Nix prefer docker
* Good, Avoids having to maintain a def file.
* Good, 100% reproducible
